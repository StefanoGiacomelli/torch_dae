# torch-dae 0.2.0

`torch-dae 0.2.0` moves the project from a control-plane foundation to an operational,
checkpoint-specific audio-model integration and profiling framework. The release adds accepted PANNs
models, runtime verification, canonical profiling evidence, agent-assisted integration/profiling
workflows, and a substantially rebuilt public documentation layer.

## Highlights

### Three accepted PANNs / AudioSet models

The repository now contains runtime-verified integrations for:

- `panns-cnn14-16k-map-0438`;
- `panns-resnet38-map-0434`;
- `panns-wavegram-logmel-cnn14-map-0439`.

Each integration records its authoritative checkpoint identity, isolated environment, waveform and
output contracts, default `[B, 2048]` embedding interface, runtime-verification evidence, and known
limitations. Checkpoint payloads are acquired from authoritative providers and are not redistributed
by the repository.

### Profiling v1 and canonical Technical Cards

Profiling v1 provides deterministic synthetic-input benchmarking with raw timing observations,
latency/throughput/RTF summaries, minimum-input discovery, architecture/resource evidence, memory
measurements, and explicit energy provenance.

Nine reviewed Technical Cards are canonical in this release: CPU single-thread, CPU native-default,
and Apple MPS contexts for each accepted PANNs model. These cards are session- and
execution-context-specific evidence, not universal hardware rankings.

### Controlled model onboarding and profiling skills

The onboarding skill now covers analysis, environment resolution, integration, runtime verification,
Model Card authoring, finalization, review bundles, and cleanup through explicit handoffs and human
review boundaries. A separate profiling skill handles planning, execution, validation, and Technical
Card review. Copy-paste-ready request templates are included in the documentation.

### Public API and documentation

The README and hosted documentation now provide a user-first path through installation, supported
models, input/output shapes, checkpoint acquisition, model execution, embedding extraction,
profiling, Model Cards, Technical Cards, CLI usage, and developer workflows. `torch-dae --version`
is available for release introspection.

### Integrity and CI

Repository validation now includes canonical Technical Card JSON/NPZ pairs and their
cross-references, hashes, raw measurements, reconstructed timing summaries, and privacy constraints.
Linux CI can statically validate platform-specific accepted environments without weakening runtime
platform enforcement.

## Compatibility and current boundaries

- Python support: 3.11 and 3.12 for the root control plane.
- The accepted PANNs managed environments are currently constrained to macOS/arm64.
- CPU and Apple MPS are locally verified for the accepted PANNs cards; CUDA remains
  upstream-declared but locally unverified.
- PANNs wrappers require mono floating-point `[B, 1, T]` tensors at the exact native sample rate and
  do not automatically resample, downmix, normalize, crop, pad, or truncate audio.
- Pretrained checkpoint payloads are not included in the package or repository.
- Profiling candidates are never promoted automatically into `technical_cards/`; canonical promotion
  remains a human-reviewed repository operation.

## Installation

```bash
pip install torch-deepaudioembedding==0.2.0
torch-dae --version
```

Use a source checkout rather than the wheel when you need the complete repository-backed registry,
environments, Model Cards, Technical Cards, agent skills, checkpoint acquisition, or profiling
workflow.
